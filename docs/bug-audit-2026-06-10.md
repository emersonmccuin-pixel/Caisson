## High — can strand a run or lose a signal

- [x] **1. Agent-host `runs` map never evicts terminal runs** — **FIXED** `be658d6d`: 15-min sweep evicts terminal runs after 6h (the server's replay window), listeners torn down at eviction; live runs untouched. Test: `terminal-run-eviction.test.ts`. — every dispatched agent stays in memory forever; a long-lived host slowly bloats, and the 5 event listeners wired per run (`wireRun`) stay attached with it.
  `packages/agent-host/src/agent-host-service.ts` — `runs.set` at :202, `ccSessionIndex.delete` at :470 is the ONLY cleanup; no `runs.delete` anywhere. *(verified)*
  Fix: on the run's `terminal` event, delete the map entry (or after a short grace window) and remove the listeners.

- [x] **2. Terminal-effects async tail swallows errors** — **FIXED** `26dd00e1`: the auxiliary human-review card block is guarded so its crash can't skip the orchestrator envelope; verifier crash already surfaced by #5's fix. — after a run finishes, the orchestrator's "agent completed/failed" envelope is delivered by a fire-and-forget async step; if it throws, the error is only logged and the orchestrator never hears the run ended. A 6-hour replay safety net partially covers it; outside that window the run is invisible.
  `apps/server/src/services/agent-run-terminal-effects.ts:217-228` (`void finishTerminalEffects(...).catch(onError)`). *(likely)*
  Fix: make the path up to envelope-enqueue synchronous (or awaited), keep only verification fire-and-forget.

- [x] **3. Deliverable accepted but run can stay "running" forever** — **FIXED** `bd55189d`: reconciler delivered-watchdog — after 60s grace re-sends complete-run to the host; after 120s finalizes locally through the terminal authority. Arms only on the durable `deliveredAt` receipt; paused runs exempt. Test: `agent-run-delivered-watchdog.test.ts`. — the deliverable route returns HTTP 200 first, then sends `complete-run` to the host detached; if that command fails AND the host's own JSONL turn-end signal never fires, the run is stuck running with no failsafe.
  `apps/server/src/features/agent-runs/routes.ts:842-848`. Code comments call it best-effort; there's no watchdog behind it. *(likely — violates positive-receipt)*
  Fix: add a watchdog that finalizes the run locally if no terminal event arrives within ~30s of a delivered contract.

- [x] **4. Silent resume-replay fallback can fake-complete a run** — **FIXED** `7a75e9cc`: transcript-read failure retries on the poll cadence instead of replaying from line 0; persistent failure → stall ladder's typed failure. — when resuming an agent, if reading the existing JSONL transcript fails, the code silently starts from line 0 and replays the whole prior conversation; a replayed old turn-end can complete the run prematurely. The code comment admits this.
  `packages/runtime/src/low-level-spawn.ts:593-602`. *(likely — violates positive-receipt)*
  Fix: typed failure on transcript-read error instead of silent `startLine = 0`.

## Medium — wrong/missing feedback, latent races, slow leaks

- [x] **5. Verification errors silently become "no verification"** — **FIXED:** verifier crash now emits `verification: {status:'pending', notes:'verifier crashed…'}` on the envelope. — if contract verification throws (transient DB/service error), the run completes with `verification: null` exactly as if no check was needed; nothing tells you acceptance criteria were never evaluated.
  `apps/server/src/services/agent-run-terminal-effects.ts:356-382`. *(likely)*
  Fix: emit a distinct `verification: { status: 'error', notes }` block.

- [x] **6. Merge-conflict card move is fire-and-forget** — **FIXED:** move awaited; failure recorded as `cardMoveError` on the `git_conflict` diary event. — on a merge conflict the run pauses for review and tries to move the card to the conflict stage, but the move isn't awaited and its failure is swallowed; you'd see a paused run with the card sitting in the wrong column and no explanation.
  `apps/server/src/services/dag-run-service.ts:476-481`. *(likely)*
  Fix: await the move; on failure, write a diary line so the pause is explained.

- [x] **7. Card can move twice across a crash** — **VERIFIED BENIGN:** a move node's target stage is static (`node.stage`, dag-executor.ts:261), so a crash-window re-run moves the card to the same stage — idempotent; worst case a duplicate `card_moved` diary line. — move nodes move the card and emit `card_moved` BEFORE the node is settled/persisted; crash in between → on restart the node re-runs and moves the card again.
  `apps/server/src/services/dag-executor.ts:260-272`. *(check-first — confirm restart re-runs a running move node)*

- [x] **8. Resume-receipt waiter survives spawn death** — **FIXED:** waiter cleared at the top of `onSpawnExit`. — if the claude.exe process exits between arming the resume receipt waiter and its timeout, the waiter isn't cleared; a later resume on the same run can be confused by the stale waiter firing.
  `packages/runtime/src/agent-run.ts:247-248, 639-676`; `onSpawnExit` (~:743) doesn't clear it. *(likely)*

- [x] **9. JSONL poll timer can be re-armed after kill** — **FIXED:** `killRequested` flag guards `tryAttach`. — tailer attachment is deferred via `setImmediate`; `kill()` clears the poll timer, but a queued attach can run afterwards and re-create it, leaving a timer polling the filesystem for a dead spawn.
  `packages/runtime/src/low-level-spawn.ts:262-264, 360-362, 611`. *(likely)*
  Fix: guard `tryAttach` on killed/exited state before arming the timer.

- [x] **10. Host lock file: stale-PID risks** — **DOWNGRADED, no change:** shutdown goes over HTTP by port (not PID); lock IS removed on graceful close (`http-server.ts:78`) and pre-spawn; escalation kills the supervisor's own child handle. Residual PID-reuse false-positive in discovery just fails the connect and the reconnect loop self-heals. — the lock file is never removed on clean shutdown, and consumers act on the recorded PID without verifying the process is actually our agent host (Windows reuses PIDs). Worst case: shutdown request sent to an unrelated process, or a new host refusing to start.
  `packages/runtime/src/agent-host-lock-file.ts:53-64` (no cleanup on exit) and `apps/desktop/src/agent-host-process.ts:60-75` (PID used unvalidated). *(likely)*
  Fix: delete lock on graceful exit; before using the PID, verify the process command line matches the host (same rule as the manual-kill memory).

- [ ] **11. No `busy_timeout` on the SQLite connection** — WAL is on but there's no busy timeout, so any concurrent writer (second process, tooling) surfaces as an immediate SQLITE_BUSY error instead of a brief wait.
  `packages/db/src/connection.ts:20-22`. *(verified — one-line fix: `pragma('busy_timeout = 5000')`)*

- [ ] **12. `isWorkItemDto` guard skips `focusedAt`** — the runtime validator checks every field except `focusedAt`, so a malformed value passes type checking and surfaces later as an opaque error (matters for Command planner focus stars).
  `packages/contracts/src/work-items.ts` — field declared :53, guard :166-188 omits it. *(verified)*

- [x] **13. Auto-updater error state can loop** — **DISMISSED:** check/download only fire from user button clicks (`use-desktop-updates.ts`); no auto-retry exists, so no loop. — after a failed download the status goes to `error`, but nothing stops the renderer from immediately re-checking and re-entering available→download→error repeatedly; no rate limit or lock.
  `apps/desktop/src/main.ts:389-408`. *(check-first — confirm renderer behavior on error)*

- [x] **14. Diagnostics dir resolution can diverge from data dir** — **FIXED:** one resolver — renderer diagnostics now share the stack config's `dataDir` (same folder as `children.log`); repo-root-walk path deleted. — diagnostics path resolution has its own fallback chain (env var → repo-root walk) separate from the supervisor's `config.dataDir`; if they disagree, diagnostics land in a different folder than the DB they describe.
  `apps/desktop/src/main.ts:444-455`. *(check-first)*
  Fix: derive diagnostics dir from the same resolved `dataDir`, one resolver.

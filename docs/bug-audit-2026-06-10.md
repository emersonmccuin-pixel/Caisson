# Bug audit — 2026-06-10

Source: 6 parallel code-review agents over server / agent-host+runtime / workflow engine / web UI / desktop+supervisor+db / mcp+contracts. Top findings hand-verified in code; confidence noted per item. Work top-down.

**Legend:** confidence = `verified` (I read the code and confirmed) · `likely` (agent-read, pattern is clear) · `check-first` (verify before fixing).

---

## High — can strand a run or lose a signal

- [ ] **1. Agent-host `runs` map never evicts terminal runs** — every dispatched agent stays in memory forever; a long-lived host slowly bloats, and the 5 event listeners wired per run (`wireRun`) stay attached with it.
  `packages/agent-host/src/agent-host-service.ts` — `runs.set` at :202, `ccSessionIndex.delete` at :470 is the ONLY cleanup; no `runs.delete` anywhere. *(verified)*
  Fix: on the run's `terminal` event, delete the map entry (or after a short grace window) and remove the listeners.

- [ ] **2. Terminal-effects async tail swallows errors** — after a run finishes, the orchestrator's "agent completed/failed" envelope is delivered by a fire-and-forget async step; if it throws, the error is only logged and the orchestrator never hears the run ended. A 6-hour replay safety net partially covers it; outside that window the run is invisible.
  `apps/server/src/services/agent-run-terminal-effects.ts:217-228` (`void finishTerminalEffects(...).catch(onError)`). *(likely)*
  Fix: make the path up to envelope-enqueue synchronous (or awaited), keep only verification fire-and-forget.

- [ ] **3. Deliverable accepted but run can stay "running" forever** — the deliverable route returns HTTP 200 first, then sends `complete-run` to the host detached; if that command fails AND the host's own JSONL turn-end signal never fires, the run is stuck running with no failsafe.
  `apps/server/src/features/agent-runs/routes.ts:842-848`. Code comments call it best-effort; there's no watchdog behind it. *(likely — violates positive-receipt)*
  Fix: add a watchdog that finalizes the run locally if no terminal event arrives within ~30s of a delivered contract.

- [ ] **4. Silent resume-replay fallback can fake-complete a run** — when resuming an agent, if reading the existing JSONL transcript fails, the code silently starts from line 0 and replays the whole prior conversation; a replayed old turn-end can complete the run prematurely. The code comment admits this.
  `packages/runtime/src/low-level-spawn.ts:593-602`. *(likely — violates positive-receipt)*
  Fix: typed failure on transcript-read error instead of silent `startLine = 0`.

## Medium — wrong/missing feedback, latent races, slow leaks

- [ ] **5. Verification errors silently become "no verification"** — if contract verification throws (transient DB/service error), the run completes with `verification: null` exactly as if no check was needed; nothing tells you acceptance criteria were never evaluated.
  `apps/server/src/services/agent-run-terminal-effects.ts:356-382`. *(likely)*
  Fix: emit a distinct `verification: { status: 'error', notes }` block.

- [ ] **6. Merge-conflict card move is fire-and-forget** — on a merge conflict the run pauses for review and tries to move the card to the conflict stage, but the move isn't awaited and its failure is swallowed; you'd see a paused run with the card sitting in the wrong column and no explanation.
  `apps/server/src/services/dag-run-service.ts:476-481`. *(likely)*
  Fix: await the move; on failure, write a diary line so the pause is explained.

- [ ] **7. Card can move twice across a crash** — move nodes move the card and emit `card_moved` BEFORE the node is settled/persisted; crash in between → on restart the node re-runs and moves the card again.
  `apps/server/src/services/dag-executor.ts:260-272`. *(check-first — confirm restart re-runs a running move node)*

- [ ] **8. Resume-receipt waiter survives spawn death** — if the claude.exe process exits between arming the resume receipt waiter and its timeout, the waiter isn't cleared; a later resume on the same run can be confused by the stale waiter firing.
  `packages/runtime/src/agent-run.ts:247-248, 639-676`; `onSpawnExit` (~:743) doesn't clear it. *(likely)*

- [ ] **9. JSONL poll timer can be re-armed after kill** — tailer attachment is deferred via `setImmediate`; `kill()` clears the poll timer, but a queued attach can run afterwards and re-create it, leaving a timer polling the filesystem for a dead spawn.
  `packages/runtime/src/low-level-spawn.ts:262-264, 360-362, 611`. *(likely)*
  Fix: guard `tryAttach` on killed/exited state before arming the timer.

- [ ] **10. Host lock file: stale-PID risks** — the lock file is never removed on clean shutdown, and consumers act on the recorded PID without verifying the process is actually our agent host (Windows reuses PIDs). Worst case: shutdown request sent to an unrelated process, or a new host refusing to start.
  `packages/runtime/src/agent-host-lock-file.ts:53-64` (no cleanup on exit) and `apps/desktop/src/agent-host-process.ts:60-75` (PID used unvalidated). *(likely)*
  Fix: delete lock on graceful exit; before using the PID, verify the process command line matches the host (same rule as the manual-kill memory).

- [ ] **11. No `busy_timeout` on the SQLite connection** — WAL is on but there's no busy timeout, so any concurrent writer (second process, tooling) surfaces as an immediate SQLITE_BUSY error instead of a brief wait.
  `packages/db/src/connection.ts:20-22`. *(verified — one-line fix: `pragma('busy_timeout = 5000')`)*

- [ ] **12. `isWorkItemDto` guard skips `focusedAt`** — the runtime validator checks every field except `focusedAt`, so a malformed value passes type checking and surfaces later as an opaque error (matters for Command planner focus stars).
  `packages/contracts/src/work-items.ts` — field declared :53, guard :166-188 omits it. *(verified)*

- [ ] **13. Auto-updater error state can loop** — after a failed download the status goes to `error`, but nothing stops the renderer from immediately re-checking and re-entering available→download→error repeatedly; no rate limit or lock.
  `apps/desktop/src/main.ts:389-408`. *(check-first — confirm renderer behavior on error)*

- [ ] **14. Diagnostics dir resolution can diverge from data dir** — diagnostics path resolution has its own fallback chain (env var → repo-root walk) separate from the supervisor's `config.dataDir`; if they disagree, diagnostics land in a different folder than the DB they describe.
  `apps/desktop/src/main.ts:444-455`. *(check-first)*
  Fix: derive diagnostics dir from the same resolved `dataDir`, one resolver.

## Low — polish, hygiene, latent footguns

- [ ] **15. Reconciler never unsubscribes its host-event listener** — `stop()` clears the tick interval but leaves the host event listener attached (the unsubscribe return value is dropped). One listener only (guarded by a `subscribed` flag), so impact is small: after stop it keeps recording heartbeats.
  `apps/server/src/services/agent-run-reconciler.ts:149-152, ~317`. *(verified)*

- [ ] **16. Modal busy-state not cleared on success** — `CreatePodModal` create and `PodDetailModal` delete only call `setBusy(false)` in the error path. Today every caller closes the modal on success so nothing visible breaks, but it triggers a setState-after-unmount and breaks the moment a caller keeps the modal open.
  `apps/web/src/components/agents/CreatePodModal.tsx:380-386`, `PodDetailModal.tsx:194-215`. *(verified — fix: `finally { setBusy(false) }`)*

- [ ] **17. Pod MCP server config allows neither `command` nor `url`** — both fields optional in the type; a config missing both is only caught later at probe time with an obscure error instead of at save time.
  `packages/domain/src/pod.ts:76-83`; probe check in `packages/mcp/src/probe.ts:68`. *(likely)*

- [ ] **18. Raw server error bodies flow to agents** — MCP tool handlers return the raw HTTP error body as the tool error message; a non-JSON error page or stack trace goes straight into the agent's context.
  `packages/mcp/src/tools/work-items.ts` (pattern repeats in agents.ts, workflows.ts). *(likely)*

- [ ] **19. `choose-folder` IPC can throw instead of returning null** — `dialog.showOpenDialog(win!, ...)` with a non-null assertion; if the window closed first, the renderer gets an unhandled rejection.
  `apps/desktop/src/main.ts:415`. *(verified-pattern, trivial fix)*

- [ ] **20. Diary shows review gates that never close on resume** — resuming a failed run resets `awaiting-review` nodes to pending with no per-node diary line, so the history reads as an open gate that was never answered. Cosmetic/debugging concern.
  `packages/workflows/src/dag/step.ts:392-395`. *(likely)*

- [ ] **21. ULID brand has no runtime validator** — any string can be cast to ULID at trust boundaries (DB hydration); an invalid ID propagates and fails opaquely later. Add a small `isUlid()` guard for boundary use.
  `packages/domain/src/ulid.ts`. *(verified-by-design)*

# T2.2 — Unified watchdog + non-terminal `stalled` warn

**Theme 2 (Track A). Depends on: nothing hard (warn-only until T1.4 for host-mode terminal). Design: `foundational-hardening-design.md` §Theme-2, slice T2.2 (line ~294).**

## Goal (plain English)
Today a quiet agent run sits "running" with no signal until it either resumes or, after 10 min, jumps straight to "failed". And in host-mode there is NO idle check at all (the liveness sweep early-returns). T2.2 adds an intermediate, visible **"stalled / quiet for Nm"** badge that appears at ~3 min of no activity in BOTH modes, while the terminal behavior at 10 min stays unchanged. It also folds the two mode-split sweeps into ONE watchdog so the stall logic lives in one place.

## What exists (verified)
- **In-process liveness sweep** `agent-run-liveness-sweep.ts` (30s, wired `index.ts:534`, gated `if (hostMode) return`): pid-dead → `unexpected-exit`; idle > 10 min → kill + `idle-timeout`. Idle = `now - max(lastActivityAt, readyAt, spawnedAt, queuedAt, jsonlMtime)`.
- **Host reconcile sweep** `reconcileAgentRunsAgainstHost` (15s, wired `index.ts:499`, gated `if (!hostMode) return`): refreshRuns + re-derive DB rows from host snapshots; emits `agent.run.changed` only on a real status change. **No idle check.**
- `touchAgentRunActivity(id,at)` writes `lastActivityAt` **without** a rev bump; `updateAgentRunStatus`/`markAgentRunTerminal`/reconcile bump rev.
- Client live store (`live-store.ts:47`) **version-dedups**: a frame whose `version` (= `rev`) is `<=` the held frame is DROPPED. `useResourceList` overlay applies equal/greater rev (last-write-wins).

## The one non-obvious constraint
A `stalled` signal does **not** change DB status, so without care it carries the **same rev** as the last `running` frame → the client store **drops it** → no badge. Therefore the stalled emit MUST out-version the last frame. There is no "bump-only" write today.

**Decision:** add `bumpAgentRunRev(id)` (rev+1, no other state) in `@pc/db`; the stalled (and un-stall) emit bumps rev first, then `announceRunChange` re-reads the post-bump row → strictly-greater rev → lands.

## Build

### 1. contracts (`packages/contracts/src/agent-runs.ts`)
- Add `'stalled'` to `AgentRunChangedReason` + `AGENT_RUN_CHANGED_REASONS` (guard derives from the array). No migration; the column is plain text.

### 2. shared idle helper (`apps/server/src/services/agent-run-idle.ts`, new)
- `WARN_MS` (default 3 min, env `PC_AGENT_STALL_WARN_MS`), `KILL_MS` (existing 10 min, env `PC_AGENT_IDLE_TIMEOUT_MS`).
- `computeIdleMs(row, { now, jsonlMtime })` — the `max(...)` logic lifted out of the liveness sweep.
- `evaluateIdle(idleMs) → 'ok' | 'warn' | 'kill'`.

### 3. rev-bump + stalled announce
- `@pc/db` repo: `bumpAgentRunRev(id): AgentRunRow | null` (`SET rev = rev+1`, return post-row).
- `agent-run-writer.ts`: `announceAgentRunStalled(runId, broadcast)` → `bumpAgentRunRev` then `announceRunChange({runId, reason:'stalled'})`; and reuse `announceAgentRunChange(reason:'reconciled')` (bump first) to **un-stall**. (announceRunChange re-reads the row, so the bump must precede it.)

### 4. unified watchdog (`index.ts` + the two sweep modules)
- Replace the two intervals with ONE `agentRunWatchdogSweep` (15s). Per tick:
  1. **hostMode only:** `await hostConnection.refreshRuns()` then `reconcileAgentRunsAgainstHost(...)` (unchanged transition logic).
  2. **both modes:** stall-warn pass — for each non-terminal `running`/`spawning` row, `computeIdleMs`; emit-once via a module-local `Set<runId>`:
     - `warn` & `!set.has(id)` → `announceAgentRunStalled`, `set.add`.
     - `ok` & `set.has(id)` → un-stall (`reconciled`), `set.delete`.
     - terminal/gone → `set.delete`.
  3. **!hostMode only (in-process):** the existing `sweepAgentRunLiveness` KILL logic (pid-dead → `unexpected-exit`; `kill` at KILL_MS → `idle-timeout`). Host-mode KILL stays **deferred to T1.4** (host liveness not yet authoritative) — host-mode is warn-only.
- Keep the inner tested functions; reuse `computeIdleMs` inside `sweepAgentRunLiveness`. Stall-warn is a new small `sweepStallWarn(deps, stalledSet)` shared by both modes.

### 5. web badge
- `use-project-agent-runs.ts` `extractFromLiveEvent`: stamp `stalled: event.payload.reason === 'stalled'` onto the record (any other reason → `false`, clears it). Higher rev makes it overlay.
- `AgentRunRecord` (`features/agent-runs/types.ts`): add `stalled?: boolean`.
- `ActivityPanel.tsx` `RunningAgentCard`: when `run.stalled`, show a muted "stalled" / "quiet" badge next to the status. Purely additive.

## Deliberate scope / deferrals (verify-core-defer-polish)
- **Cold page-reload loses the badge** until the run un-stalls/terminates: the HTTP seed doesn't compute idle (would need jsonl-mtime server-side per row), and the emit-once in-memory set won't re-fire. The slice-018 guarantee (survives client *timeline rebuilds*) IS met — the stalled frame sits in the identity-keyed store. Cold-reload recovery = a later polish (derive `stalled` in the list route). **Logged, accepted.**
- **Host-mode terminal stall** (host-lost/host-crashed finalization) = T1.4/T2.3, not here. Host-mode warn-only.

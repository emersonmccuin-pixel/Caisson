# T3.1 — Migrate the 3 live-UI stragglers onto the identity-keyed live store

Theme 3, slice 1 of the 015→018 "one client door" arc. Branch `refactor/auto-pathway`.

## Goal
Move the three views that still positional-scan the chat `events[]` (rich-link
invalidator, mailbox inbox, sessions rail) onto the identity-keyed live store
(`live-store.ts`), so they update live during an active agent session (when the
chat timeline re-derives and integer cursors miss frames). Reconcile-first:
migrate only — do NOT delete timeline retention or the WS-handler dispatch (that
is T3.3). Plus one writer fix so mailbox message- and delivery-changed frames
stop colliding on the same store key.

## Selectors — all already present (T3.1 adds NONE)
`apps/web/src/store/live-store.ts` already exports everything needed:
- `useLiveEvents(entity, projectId)` — project + global-scope frames for a project view.
- `useLiveEntitySignature(entity, projectId)` — refetch-key string, flips only on a real change for that entity.
- `useLiveGlobalEvents(entity)` / `useLiveGlobalSignature(entity)` — project-less (`projectId === null`) variants. Added by T1.1 for the host-health pill; reuse as-is for the global mailbox inbox.

So T3.1 touches: 3 web consumers + 1 server writer + 1 reducer nonce. No store changes.

## Straggler 1 — rich-link invalidator
File: `apps/web/src/hooks/use-rich-link-invalidator.ts`
Caller: `apps/web/src/App.tsx:134` `useRichLinkInvalidator(ws.events)`

### Current (the scan)
`:18-42` — takes `events: WsEnvelope[]`, keeps a `useRef(0)` positional cursor
`lastIdx`, loops `events[lastIdx..length]` each render, and on
`work-item.changed` / `attachment.changed` / legacy `attachment-changed` frames
calls `invalidateByWorkItemId` / `invalidateByAttachmentId`. Positional → misses
frames after a timeline rebuild.

### Target
Drive eviction off the store, not the array, with a **version-keyed evicted-set**
so each entity evicts once per new version (not every render):
- `const wiEvents = useLiveEvents('work-item', projectId)`
- `const attEvents = useLiveEvents('attachment', projectId)`
- Keep a `useRef<Map<string, number>>` of `entityId → lastEvictedVersion`. In an
  effect over each list, for every event whose `version` (or `cursor` for
  null-version) is newer than the recorded one, call the matching `invalidateBy*`
  and record the new version. Identity-keyed = rebuild-proof; version-keyed = no
  redundant evictions.
- Signature change: hook takes `projectId` (selectors are project-scoped). Change
  `App.tsx` call to `useRichLinkInvalidator(activeProject?.id ?? null)`; drop the
  `ws.events` argument.
- Drop the legacy `attachment-changed` raw-envelope branch ONLY if confirmed dead
  (see Open Q2); otherwise leave it out of scope and do NOT re-add an `events[]` scan.

### What stays
The chat timeline still carries these frames (reconcile-first). `use-rich-link-data.ts`
(`invalidateByWorkItemId`/`invalidateByAttachmentId`) is unchanged.

## Straggler 2 — mailbox inbox
File: `apps/web/src/hooks/use-mailbox-inbox.ts`
Helper: `apps/web/src/features/mailbox/live-events.ts` (`scanMailboxLiveEvents`)
Caller: `apps/web/src/features/mailbox/MailboxInbox.tsx:44` `useMailboxInbox(scope, events)`

### Current (the scan)
`:52-56` — `scanMailboxLiveEvents(events, scanIndexRef.current, seenRef.current)`,
a positional scan from `scanIndexRef` folding `mailbox.message.changed` /
`mailbox.delivery.changed` / `pending-interaction.changed` into a "should refetch"
flag, deduped by `event.id`. `scope` is `{projectId}` or `{global:true}`.

### Target
Replace the array scan with signature-keyed refetch effects:
- Project scope: `msgSig = useLiveEntitySignature('mailbox-message', projectId)`,
  `piSig = useLiveEntitySignature('pending-interaction', projectId)`;
  `useEffect(() => refetch(), [msgSig, piSig])`.
- Global scope (project-less inbox): `useLiveGlobalSignature('mailbox-message')`
  (pending-interaction is project-scoped by contract, so the global inbox keys
  only on the message signature).
- Keep the initial `refetch()` on scope change + the `dismissedAt === null`
  client exclusion.
- Drop the `events` arg, `scanIndexRef`, `seenRef`, the `scanMailboxLiveEvents`
  import. Update `MailboxInbox.tsx` to `useMailboxInbox(scope)`.
- `scanMailboxLiveEvents` / `live-events.ts` STAYS (still used by tests / possibly
  other consumers — grep; do not delete in T3.1).

### Writer-side fix (the key collision) — REQUIRED
File: `packages/app-services/src/mailbox/mailbox-service.ts`
- `buildDeliveryDraft` (`:285-307`) emits `entity:'mailbox-message'`,
  `entityId: delivery.messageId`, `version: delivery.attempts`.
- `buildMessageDraft` (`:266-283`) emits `entity:'mailbox-message'`,
  `entityId: message.id`, `version: null`.
- Same store key `mailbox-message::<messageId>` → message frame (version null,
  last-write-wins) and delivery frame (version attempts) overwrite / mis-dedup.

**Fix (one line):** in `buildDeliveryDraft`, `entityId: delivery.id` (the delivery
row id), not `delivery.messageId`. Delivery frames now key
`mailbox-message::<deliveryId>`, distinct from the message frame.

**Wire-safe because:**
- The delivery guard `isMailboxDeliveryChangedLiveEvent` (`packages/contracts/src/mailbox.ts:464-471`)
  checks only `type`/`entity`/payload shape — never `entityId === messageId`.
- The payload carries both `deliveryId` and `messageId`; consumers read
  `payload.messageId`, not the envelope `entityId`.
- The outbox (`live-outbox.ts insertLiveEvent`) is append-only by `seq` with no
  per-(entity,entityId) constraint or coalescing → replay unaffected.
- Rides the same relay door (`insertLiveEvent`, no `broadcast*`) → server
  `no-bypass-gate.test.ts` unaffected. Union/guards/frame type untouched.

### What stays
Chat-timeline retention of mailbox frames; the `scanMailboxLiveEvents` helper.

## Straggler 3 — sessions rail
File: `apps/web/src/components/SessionsRail.tsx`
Plumbing: `LeftRail.tsx:70` passes `events`; `useProjectWs` returns `events` + `aggregates`.

### Current (the scan)
`:79-91` — `[...events].reverse().find(...)` for `type === 'session-changed'` OR a
`session-title` relay frame; on a hit, refetches `runtimeApi.listSessions`.

### Target — split the two triggers
- **`session-title` (relay fact):** `titleSig = useLiveEntitySignature('session-title', project?.id ?? null)`;
  refetch `useEffect(..., [titleSig, project?.id])`.
- **`session-changed` (chat-LIFECYCLE envelope, NOT a relay fact):** consume from
  typed reducer state, not the array. Reducer tracks `activeSessionId` but has no
  counter that ticks on EVERY session-changed (resume-to-same-id wouldn't flip
  `activeSessionId`). **Add `sessionChangedNonce: number`** to
  `ChatSessionReducerState` (init 0 in `createChatSessionState`); increment in
  `applySessionChanged` (`:387-417`) for BOTH new-session and resume branches.
  Expose via `UseProjectWsResult` (`use-project-ws.ts:54-62` + return) sourced from
  `sessionState.sessionChangedNonce`. Thread `LeftRail` → `SessionsRail`; rail
  refetches on the nonce.
- Remove the `events` prop + the `reverse().find` from `SessionsRail`. Update
  `LeftRail.tsx` to pass `sessionChangedNonce` instead of `events`.

### What stays
Chat-timeline retention of session-changed/session-title; the reducer's existing
behavior (we only ADD a monotonic counter).

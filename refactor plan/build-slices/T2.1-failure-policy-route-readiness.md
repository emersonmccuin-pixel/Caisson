## Problem (what the code actually does)
- **Dominant restart-window symptom = TCP connection-refused, not a 500.** Migrations run before `server.listen`, so the ~1s window is "old proc gone, new not yet accepting". The web client `getJson` (`apps/web/src/api/http.ts`) turns a refused fetch into a thrown error with **no retry** → cold-load panels throw, "need to refresh".
- **Second no-retry client:** the spawned agents' `pc-rig` MCP server calls back into the API over localhost with raw `http.request` and **no retry** (`packages/mcp/src/tools/context.ts`). During an API restart an agent's tool call fails outright.
- The live-events replay route returns a blanket **500** on any throw (`features/live-events/routes.ts:38`) — a transient DB-busy looks identical to a real error and the client can't tell to retry.

## What we build
1. **`apps/server/src/services/failure-policy.ts`** (new, server-only). `classifyThrow(err) → {kind:'transient'|'terminal', reason}` (SQLITE_BUSY/LOCKED → `db-busy`; AbortError/timeout → `host-blip`; ECONNREFUSED/RESET/ETIMEDOUT/EPIPE → `network`; else `terminal`). `withTransientRetry(fn,{attempts,baseMs,maxMs})` exp-backoff+jitter, retries transient only. Distinct from workflow `retry-policy.ts` — keep both.
2. **Route readiness** — live-events replay route catches a transient throw → **503 + `Retry-After`** (not 500). Canonical example; other DB-read GETs adopt the same one-liner as needed. (LiveEventCursorError stays 400.)
3. **Web `getJson` bounded retry** — `apps/web/src/api/http.ts` `fetchWithRetry`: retry on **503** (all methods — server says "not ready"; honors `Retry-After`) and on a **thrown network error** (GET only — idempotent; a refused connection never landed). Posts do NOT retry network errors (avoid double-submit). Bounded: 4 attempts, ~120ms base, 1s cap.
4. **pc-rig MCP localhost retry** — `packages/mcp/src/tools/retry.ts` `withConnRetry(attempt,opts)`: retry when the attempt throws a transient conn-error code OR resolves `status===503`. `context.ts` wraps each `httpWithBody`/`httpWithoutBody` call. Duplicated (not shared dep) — same backoff contract. ECONNREFUSED (pre-send) is the realistic restart symptom and is safe to retry for any method.

## Tests
- `apps/server/test/failure-policy.test.ts` — classifyThrow taxonomy; withTransientRetry retries transient + gives up on terminal + respects attempts.
- extend `apps/server/test/live-events-routes.test.ts` — a transient throw from the replay fn → 503 + Retry-After; a terminal throw → 500.
- `apps/web/test/http-retry.test.ts` — getJson retries 503→200, retries thrown-network→200 (GET), gives up after attempts; postJson retries 503 but NOT thrown-network.
- `packages/mcp/test/localhost-retry.test.ts` — withConnRetry retries ECONNREFUSED then resolves; retries 503; gives up; passes terminal through.

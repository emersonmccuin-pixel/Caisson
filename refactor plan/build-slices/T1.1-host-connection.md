## 1. Goal + the one-line win

One long-lived `HostConnection` wrapping the existing `HttpAgentHostClient` + lock-file discovery, with
the **lock file as the SOLE source of host identity** — liveness, re-discovery, dispatch, events, health all
through ONE conduit.

**The win (kill T1-A):** the dev-supervisor crashes the host → respawns it on a NEW OS-assigned port →
rewrites the lock → **the next dispatch succeeds with NO API restart** (today every dispatch fails
`host-unavailable` until the API itself restarts, because the route captured the client by-value at boot).
A `host-health` pill flips `reconnecting`→`connected` and recovers.

Two changes carry the win:
- the by-value route capture (`index.ts:1000` work-items, `:1016` agent-runs) becomes a `getHostConnection` closure;
- `HostConnection.sendCommand` re-discovers + reconnects on a dead baseUrl instead of failing.

## 3. The HostConnection contract (as it will be implemented)

`HostConnection` must satisfy `AgentHostReattachClient` (`agent-host-reattach.ts:49`) so every existing
consumer compiles unchanged. That interface is exactly:

```ts
// agent-active-runs.ts:70
interface AgentHostCommandSender {
  sendCommand(cmd: AgentHostCommand): AgentHostCommandResponse | Promise<...> | void;
}
// agent-host-reattach.ts:49
interface AgentHostReattachClient extends AgentHostCommandSender {
  listRuns(): readonly AgentHostRunSnapshot[];
  onEvent?(listener: (e: AgentHostEvent) => void): (() => void) | void;
}
```

Implemented surface (superset — extra members are additive, don't break the structural match):

```ts
export interface HostConnection extends AgentHostReattachClient {
  // identity — derived from the lock file, never cached across a host-id change
  currentIdentity(): AgentHostIdentity | null;     // {hostId,pid,startedAt,protocolVersion}
  health(): HostHealth;
  isConnected(): boolean;

  // the ONE conduit (existing-shape; now auto re-discovers + reconnects)
  sendCommand(cmd: AgentHostCommand): Promise<AgentHostCommandResponse>;
  listRuns(): readonly AgentHostRunSnapshot[];      // last-known cache
  refreshRuns(): Promise<readonly AgentHostRunSnapshot[]>;
  onEvent(listener: (e: AgentHostEvent) => void): () => void;  // multiplexed, survives reconnect

  // health signal (UI pill now; Theme 2 T2.3 watchdog later)
  onHealthChange(listener: (h: HostHealth) => void): () => void;
  close(): void;
}

export type HostHealth =
  | { state: 'connected';    hostId: string; pid: number; lastOkAt: number }
  | { state: 'reconnecting'; lastError: string; since: number }   // transient
  | { state: 'down';         lastError: string; since: number };  // terminal (protocol mismatch / no lock)
```

### Internal behavior

- **Identity = lock file only.** `discoverAgentHostEndpoint({dataDir})` (reused as-is) → `{lock, baseUrl}`.
  `currentIdentity()` returns `{hostId,pid,startedAt,protocolVersion}` from the last good lock, or null.
- **One inner client per host-id.** Hold a private `HttpAgentHostClient` for the current baseUrl + an
  `eventUnsub`. On any reconnect that changes the host-id, `close()` the old inner client and build a new one.
- **Persistent multiplexed emitter.** `HostConnection` owns its OWN `EventEmitter`/listener set. External
  `onEvent` listeners attach to IT, not to the inner client — so they survive a reconnect. The connection
  forwards the inner client's `onEvent` into its own emitter; after a reconnect it re-subscribes the inner
  client and keeps forwarding to the SAME external listeners.
- **`sendCommand` reconnect (the core):**
  1. try `inner.sendCommand(cmd)`.
  2. on a connection-class throw (`fetch failed` / `ECONNREFUSED` / `AbortError` / non-OK HTTP, matched off
     the existing `fetchCommandError` shapes) → **re-discover ONCE** via the lock file, swap baseUrl, retry
     ONCE. Health → `reconnecting` during the attempt.
  3. if the lock's `hostId` changed → it's a new host: build a fresh inner client, `hello()`, `startEventStream()`
     (`/events?after=lastSeq`), `refreshRuns()`, re-forward events to the persistent emitter, health →
     `connected`.
  4. protocol mismatch (lock `protocolVersion !== AGENT_HOST_PROTOCOL_VERSION`) or no lock / pid dead and no
     respawn within the retry → health → `down`, throw loud (NEVER dispatch into an incompatible/absent host).
  5. success on the original or retried call → health → `connected` (`lastOkAt = now`).
- **Liveness monitor (behind backoff, no storms):** a slow heartbeat (e.g. 10s, `unref`'d) that does
  pid-alive + `GET /health` + compares returned `identity.hostId`/`protocolVersion` to the lock. A health
  probe NEVER forces a reconnect on its own except to flip the published `HostHealth`; the authoritative
  re-discover happens lazily inside `sendCommand`. Backoff: while `reconnecting`/`down`, widen the poll
  interval (exp, capped) so a persistently-dead host doesn't hammer `/health`.
- **`onHealthChange`** fires on every state transition (dedup identical states) → drives the outbox emit
  (§5) + the UI pill.
- **`lastSeq` continuity:** track the max event `seq` seen; on reconnect, the new `/events?after=lastSeq`
  resubscribe avoids replaying the whole backlog (the inner `HttpAgentHostClient` already tracks `lastSeq`
  internally and starts the stream from it — preserve that by seeding the new inner client's stream from the
  connection's tracked `lastSeq`).

### Construction / wiring

- Factory `createHostConnection({dataDir, requestTimeoutMs?, onProtocolError?, fetch?, now?, isPidAlive?,
  discoverEndpoint?, heartbeatMs?})` — all overridable for tests (mirrors `ResolveAgentHostClientForBootOptions`).
- The connection is **lazy/tolerant of an absent host at boot**: if discovery finds nothing, health = `down`
  (or a benign `reconnecting`) and the first `sendCommand`/heartbeat that finds a lock connects. This replaces
  the boot `.catch(()=>null)` silent-null for the dispatch path (the boot resolver stays for now — reconcile-first).

## 5. The `host-health` entity definition (exact)

**ONE global-scope live-event** on the canonical envelope (defined here; consumed later by Theme 2 T2.3).

- **scope:** `'global'`, **projectId:** `null` (enforced by `assertScopeProjectInvariant`).
- **type:** `'host-health.changed'`.
- **entity:** `'host-health'`.
- **entityId:** a STABLE constant sentinel `'host-health'` (the store skips null-entityId frames; a constant
  key means every update dedupes to one store slot — exactly one pill). `version: null` (last-write-wins;
  the monotonic outbox `seq`/`cursor` orders them — the global selector keys off `version ?? cursor`).
- **payload:**
  ```ts
  // contracts/src/live-events.ts
  export interface HostHealthSnapshot {
    state: 'connected' | 'reconnecting' | 'down';
    hostId: string | null;
    pid: number | null;
    lastError?: string;

  export interface HostHealthChangedLivePayload { health: HostHealthSnapshot }
  ```

  (Reconciled with the design's `{state, hostId, pid, lastError?, since}`; `hostId`/`pid` nullable for the
  `down`/no-lock case.)

  `isLiveEventEntity`) + the payload type/guard.

- **emit:** `apps/server/src/services/host-health-writer.ts` `announceHostHealth()` (in-txn `insertLiveEvent`,

## Decisions made

- **Optional `GET /api/agent-host/health` route — SKIP this slice.** The pill consumes the durable
  `host-health` relay frame (the sanctioned one-door mechanism, reconnect-replayable). A separate one-shot
  HTTP probe would be a SECOND source for the same fact (and a poll the client must own), contradicting the
  one-door model and adding nothing the pill needs. If a non-WS health check is later wanted (e.g. for
  `/api/dev/status`), add it in T2.3 alongside the banner. Justification: avoid a parallel read path.
- **`entityId` = constant `'host-health'`** (not the hostId) so the pill is exactly one store slot that
  updates in place across host-id changes; ordering by the monotonic outbox cursor handles last-write-wins.
- **Add `useLiveGlobalSignature`/`useLiveGlobalEvents` to `live-store.ts`** rather than relaxing the existing
  project selectors — the project selectors' null-projectId early-return is load-bearing (a project view must
  not pick up unrelated global frames the same way). This is the global selector T3.1 was already slated to add.
- **`HostHealthSnapshot` lives in `@pc/contracts`** as the single source; `HostConnection.HostHealth` is the
  same shape (server-internal, with the connected/reconnecting/down discriminant) — emit maps it to the
  snapshot. Keeps server + client agreeing on the wire payload.

## 10. Risks

- **Reconnect storms.** Gate health polling + re-discovery behind exp backoff (cap ~30s); a probe never
  forces a reconnect — only `sendCommand` does, and only once per call. Heartbeat `unref`'d.
- **Double-delivery during re-subscribe.** The `/events?after=lastSeq` window can replay an event already
  applied. Mitigated by the EXISTING idempotent terminal application (`applyHostTerminalSnapshot`,
  `agent-host-reattach.ts:289`) + the connection tracking `lastSeq`. Don't add new dedup.
- **Protocol mismatch must be terminal, not silent.** A lock with a wrong `protocolVersion` → health `down`
  + loud throw; never build an inner client against it (the current boot resolver's `.catch(()=>null)` silent
  degrade is exactly the failure mode we're replacing for the dispatch path).
- **Boot with no host.** Connection tolerates an absent lock at construction (health `down`/`reconnecting`,
  no throw) so the server boots; the first lock that appears connects lazily.
- **Pill placement diff.** Keep the mount a one-line addition in existing chrome; do not restructure layout
  (avoids a web review surprise).

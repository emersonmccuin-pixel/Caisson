# T3.2 — Migrate the `project.changed` background scan onto the live store

Theme 3, slice 2 of the 015→018 "one client door" arc. Branch `refactor/auto-pathway`.

## Goal
Stop refetching the whole project list on every WS frame. Drive the project-list
refetch off the identity-keyed live store's global `project` signature, and feed the
background socket fleet (`useAllProjectsWs`) into that store so global `project.changed`
frames from non-active projects land. Reconcile-first: wire the new path beside the old
scan, prove it, then delete the scan in the same slice.

## Current behavior (the blunt pattern)
- `apps/web/src/App.tsx:143-166` — a `useEffect` keyed on
  `[ws.events, backgroundWs.events, storeProjectChangedCursor]`. Every time EITHER
  socket's `events[]` array gets a new identity (ANY WS frame), it positional-scans both
  arrays (`scanProjectChangedEvents`, `apps/web/src/features/projects/live-events.ts:44`)
  from a ref cursor and on any `project.changed` hit calls
  `projectsApi.listProjects().then(setProjects)`.
- This is the freeze engine fixed in `c6288afd`: the effect fires on array identity, not on a
  real project change → during an active session it re-runs constantly; `setProjects` returns
  a new array → re-renders → churn. T3.1's pattern (signature string, not array identity) is
  the structural fix.
- `App.tsx:168-196` — a SECOND effect does HTTP catch-up
  (`liveEventsApi.listEvents({type:'project.changed'})`) on connect/reconnect, deduped by
  `seenProjectChangedLiveIdsRef`. Cold-load / gap-recovery path, NOT positional — KEEP it.
- `useAllProjectsWs` (`apps/web/src/hooks/use-all-projects-ws.ts:187-206`) does NOT feed the
  store today — its `message` handler only pushes its own `events[]`. Global `project.changed`
  on a BACKGROUND socket never reaches the store.
- `use-project-ws.ts:280-290` DOES feed the store for the active socket (post-018). T3.2
  closes the background-fleet half.

## Why the store is the right key
`packages/contracts/src/projects.ts:96-102` — `project.changed` is `entity:'project'`,
`scope:'global'`, `projectId:null`, `version:null`. Global scope → `useLiveGlobalSignature('project')`
is the correct selector (NOT `useLiveEntitySignature('project', null)` — that early-returns).
Last-write-wins on `cursor`.

## BLOCKER — reorder frames have `entityId: null`
`packages/app-services/src/projects.ts:139,191` call `projectChanged('reordered')` with NO
project → `buildProjectChangedLiveEventDraft` (`:270-282`) sets `entityId: null`. The store
drops null-entityId frames (`live-store.ts:41` `if (!ev.entityId) return;`). So a reorder
never enters the store and a store-signature refetch would MISS it. (created / updated /
soft-deleted carry `projectIdChanged` → fine.)

**Fix (server, wire-safe):** give reorder frames a stable synthetic id. In
`buildProjectChangedLiveEventDraft`, `entityId: (payload.projectIdChanged as DomainULID | undefined) ?? ('reorder' as DomainULID)`.
Mirror in `toProjectChangedLiveEvent` (`:294`) and `buildEphemeralProjectChangedLiveEvent`
(`:311`) so relayed/ephemeral match the draft (verify whether the outbox round-trips
`entityId` faithfully — if so, only the draft + ephemeral builders change). Version is null
(last-write-wins) → each reorder overwrites `project::reorder` and the global signature
advances → refetch fires.

**Wire-safe:** guard `isProjectChangedLiveEvent` (`:242`) never checks `entityId`; consumers
read `payload`; outbox append-only by `seq`, no per-entityId constraint; rides
`insertLiveEvent` (relay door, no `broadcast*`) → `no-bypass-gate` unaffected. Union/guards/
frame type untouched.

## Target
1. `useAllProjectsWs` feeds every `live-event` frame into the store (mirror
   `use-project-ws.ts:289`) AND advances the per-project live cursor (mirror `:280-284`);
   handle `live-reset` (Open Q1).
2. App refetches off `const projectSig = useLiveGlobalSignature('project');` in an effect with
   deps `[projectSig]` ONLY. `setProjects`' new array can't re-trigger it.
3. Delete the positional scan effect (`:143-166`), `scanProjectChangedEvents` import + call,
   `projectChangedScanRef`. Keep what the HTTP effect still needs (step 5).

## Step-by-step

### 1. Server writer — make reorder frames storable
`packages/app-services/src/projects.ts`
- `buildProjectChangedLiveEventDraft` (`:270`): `entityId` fallback `'reorder'` when no
  `projectIdChanged`.
- `toProjectChangedLiveEvent` (`:284`) + `buildEphemeralProjectChangedLiveEvent` (`:301`): same
  fallback so relayed + ephemeral match (verify outbox round-trips `entityId`; if it does,
  only draft + ephemeral change).

### 2. Background fleet — feed the store
`apps/web/src/hooks/use-all-projects-ws.ts`
- Import `useLiveStore` + cursor helpers (`advanceLiveCursor`, `clearLiveCursor`,
  `liveCursorScopeForProject`).
- In the `message` handler (`:198-205`), after accept-filter + `server-pong` early-return,
  alongside the existing `onEvent(env)`:
  - `live-event` → `advanceLiveCursor(...)` + `useLiveStore.getState().applyEnvelope(env)`
  - `live-reset` → `clearLiveCursor(...)` + `useLiveStore.getState().clearAll()` (+ Open Q1) + return
  KEEP `onEvent(env)` (still consumed by `useProjectUnread`).

### 3. App — signature-driven refetch (beside the old scan first)
`apps/web/src/App.tsx`
- `import { useLiveGlobalSignature } from '@/store/live-store';`
- `const projectSig = useLiveGlobalSignature('project');`
- New effect:
  ```
  useEffect(() => {
    if (projects === null) return;            // skip before first cold load
    void projectsApi.listProjects().then(setProjects).catch(() => {});
  }, [projectSig]);
  ```
  Deps EXACTLY `[projectSig]` — a stable string. Reading `projects` without depping it is
  deliberate (depping it reintroduces the c6288afd loop); if lint auto-adds it, hoist the
  null-check behind a ref or eslint-disable with a one-line reason.

### 4. Delete the old scan (same slice, after the new path is in)
`apps/web/src/App.tsx` — delete the positional effect (`:143-166`), `projectChangedScanRef`
(`:49`), the `scanProjectChangedEvents` import (`:19`). Do NOT delete `scanProjectChangedEvents`
from `live-events.ts` (reconcile-first; grep — tests/gate may import it).

### 5. Reconcile the HTTP catch-up effect (`App.tsx:168-196`)
KEEP it (gap-recovery, not a positional scan). It still needs the cursor writer + seen-id ref.
Step 4 deletes ONLY the array-scan effect + `projectChangedScanRef`; keep
`storeProjectChangedCursor`/`projectChangedCursorRef`/`seenProjectChangedLiveIdsRef` for this
effect. Net: live path (store signature, both sockets) + cold/gap path (HTTP) — both
idempotent, no double-trigger fight (live path no longer keys on `ws.events`).

## Open questions / risks
1. **Background `live-reset`.** Active socket bumps `useWsEpoch` too; the fleet has no epoch
   wiring. Lowest-risk: `clearAll` + clear cursor and let the HTTP catch-up reconcile. Flag.
2. **Refetch-loop guard.** New effect deps MUST be `[projectSig]` only. Confirm lint doesn't
   auto-add `projects` (would reintroduce c6288afd). Hoist behind a ref if so.
3. **Double cursor advance.** A global frame can hit active + background sockets; both
   `applyEnvelope` (store dedups) + advance DIFFERENT scoped cursors — fine.
4. **`entityId:'reorder'` collision.** Project ids are ULIDs, never literal `reorder`; if a
   future reason also lacks a project, give it a distinct literal.
5. **`storeProjectChangedCursor` partial deletion.** Used by BOTH effects — keep it for the
   HTTP effect after deleting the scan effect.

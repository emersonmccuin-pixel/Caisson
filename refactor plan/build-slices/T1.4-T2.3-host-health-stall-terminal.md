Reconcile-first: extend the existing watchdog/reattach paths in place; build the banner BESIDE the pill; one live-verify at a time.

---

## 1. Objective

**Plain English.** Two paired fixes that ride the same authoritative host-liveness signal T1.1 already publishes.

- **T2.3 (the surface):** when the agent host goes away, the app shows ONE clear "agent host unreachable" banner instead of a pile of identical failed agent cards. Two smaller gaps close with it: (a) when the server can't reach the host at startup it currently degrades to the old in-process path *silently* — it should instead announce the host is down so the banner shows; (b) a fresh page reload currently shows a *blank* host pill until the next host event — it should show the current host state right away.
- **T1.4 (the terminal):** today, if the host dies mid-run, the run sits "running" forever — the continuous reconcile leaves host-missing rows untouched on purpose (it couldn't tell "host genuinely gone" from "host mid-restart"). Now that the HostConnection knows authoritatively whether the host is reachable, we can safely finalize those orphaned runs as a surfaced `host-lost` failure instead of leaving them stuck.

**Technical.** Consume the existing T1.1 `host-health` global live-event into an app-level banner (`down`/`reconnecting`). Replace the boot-connect `.catch(()=>null)` silent degrade with a `down` health emit. Add a client cold-load HTTP seed for global host-health so the pill is correct on reload. In the watchdog's host-mode branch, once `hostConnection.health()` is authoritatively `down` AND a non-terminal host-mode row is absent from the host's `list-runs` for N consecutive ticks, finalize it terminal `host-lost` via `applyAgentRunTerminalEffects` (full effects + the existing `failed` live-event), removing the T2.2 host-mode warn-only cap.

## 5. Key decisions (confirm before build)

- **D1 — "authoritative liveness" definition (the false-positive guard).** A host-mode non-terminal row is finalized `host-lost` ONLY when ALL hold: (1) this tick's `hostConnection.refreshRuns()` **completed** (did not throw); (2) `hostConnection.isConnected() === false` (the connection is in `reconnecting`/`down`, i.e. no live inner client) OR the run is absent from a *successful* `list-runs` of a *connected* host (host alive but doesn't own this run); (3) the run has been continuously absent for `>= 2` ticks (~30s at 15s cadence); (4) not `paused`-with-open-ask. This is conservative: a mid-respawn window (connection `reconnecting`, `refreshRuns` throwing) does NOT increment the counter, so a host bouncing on a new port never false-kills a live run. **Confirm the 2-tick / ~30s threshold** (could be env `PC_HOST_LOST_TICKS`).
- **D2 — finalize cause = `host-lost`, not `host-crashed`.** Match the boot-reconcile precedent (`host-lost`). `host-crashed` would imply we observed a crash; we only observe absence. Reserve `host-crashed` for a future explicit host-exit signal. **Confirm.**
- **D3 — keep `reconnecting` (not `down`) for a missing lock; surface via the banner.** A normal dev cold-start has the host racing up; flashing `down`/red would be noise. The banner shows `reconnecting` as degraded-but-recovering. Protocol-mismatch stays the only true `down`. This satisfies "boot-connect failure not silent" without lying about terminality. **Confirm** (alternative: emit `down` after N failed heartbeats — more code, redder UX).
- **D4 — cold-load seed scope = host-health only this slice.** Generalizing the seed to all global entities is a T3.x concern. **Confirm** seeding just `host-health.changed` here.
- **D5 — no new contract reason/badge for host-lost.** The card shows the standard `failed` state; the cause rides `failureCause`. If you want a distinct "host lost" card affordance, that's a contract add — **flag now if you want it**, else defer.

## 9. Live-verify bar (one at a time; never restart the stack unasked)

Pre: gated `pnpm dev:app` on the new source; host-health pill `connected`.

**T2.3:**
1. **Cold-load seed:** with the host up, hard-reload the web app. Pill shows `connected` *immediately* (pre-fix: blank until the next transition). ← seed proof.
2. **Banner on down/reconnecting:** kill the agent-host child PID. Within a heartbeat, the pill flips `reconnecting` AND the app-wide banner appears ("Reconnecting to agent host…"). Dev-supervisor respawns the host on a new port → pill→`connected`, banner disappears — no API restart, no manual refresh.
3. **Second tab (never reloaded):** shows the same banner transitions (global frame rides `broadcastAll`).

**T1.4:**
4. Dispatch a host-backed agent → `running`; note the host child PID.
5. **Kill the host child AND prevent respawn** (or kill repeatedly so it can't re-own the run). Within ~2 watchdog ticks (~30s) the run escalates from `running` to a **surfaced `failed` (cause host-lost)** card — NOT forever-running (pre-fix: stuck `running`). Banner shows host degraded throughout.
6. **False-positive check:** dispatch a fresh run, then crash the host so the dev-supervisor respawns it on a new port mid-run. The run must **survive** (reconnect re-owns it) — it must NOT get host-lost'd during the respawn window. ← the conservatism proof.
7. **Recovery:** after the host is back, a NEW dispatch works (T1.1/T1.2 self-heal) and the banner is gone.
